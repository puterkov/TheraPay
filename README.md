# TheraPay

ניהול קליניקה למטפלת אחת: ממשק שמתחיל בסלולר, רישום ידני של פגישות, הודעות WhatsApp וחשבוניות מס־קבלה ב־Morning.

## מה נבנה

- מסך פתיחה עם דשבורד כהה, הוספת פגישה ומטופל וסיכומי נתונים. מסכים נפרדים למטופלים, פגישות, גבייה ומסמכים; ניווט תחתון בסלולר ותפריט צד במחשב. פגישות וגבייה מוצגות בטבלאות קומפקטיות עם פרטי שורה נפתחים. המבנה הוחלף לאפשרות הראשונה לפי בחירת המשתמש.
- חיווי גלוי למספר המטופלים והפגישות שהשרת החזיר. בעיית הפגישות החסרות בחיבור האמיתי עדיין דורשת בדיקה מול הגיליון; שינוי העיצוב אינו תיקון של מקור הנתונים.
- פרטי החיבור, רענון הנתונים וההתנתקות נמצאים במסך הגדרות נפרד הנפתח מכפתור ⚙ בראש האפליקציה. אין טופס חיבור בדשבורד.
- הדשבורד מציג סיכומים וכפתורי הוספת פגישה ומטופל בתחתית, עם אייקונים וכיתוב קצר, ללא אזור גבייה ותזכורות וללא הודעות ספירת טעינה. במטופלים מוצגים פרטים בלבד ללא כפתורי גבייה.
- רשימת הפגישות מאפשרת סינון משולב לפי מטופל ולפי שם חודש ושנה, עם אפשרות להצגת הכול. הסינון נשמר ברענון הנתונים.
- בטבלת הפגישות מוצגים תאריך, מטופל, סכום וסטטוס; בטבלת הגבייה מוצגים סימון, תאריך, סכום וסטטוס עבור המטופל שנבחר. מספר חשבונית, אמצעי תשלום וקישור למסמך נמצאים בפרטי השורה. אפשר לפתוח פרטים בלחיצה על השורה או באמצעות כפתור התאריך במקלדת. לחיצה על תיבת הסימון משנה רק את הבחירה ואינה פותחת פרטים.
- במסך הגבייה אין סכום חוב כולל שאינו קשור למטופל הנבחר. הסכום בתחתית מציג את שם המטופל ואת מספר הפגישות שנבחרו עבורו. כלל הבחירה האוטומטית של חובות קודמים נשמר.
- כשל זמני ברענון אינו מאפס חיבור תקין. לאחר תשובת הפקה מוצלחת, הפגישות שנבחרו מסומנות כשולמו גם בממשק המקומי לפני הרענון. אם הרענון נכשל מוצגת הודעה ונשמר קישור המסמך; שגיאת AUTH מפורשת בלבד מבטלת את קוד הגישה השמור.
- ״זכור אותי במכשיר הזה״ שומר את סיסמת הקליניקה בדפדפן עד להתנתקות יזומה או לשינוי הסיסמה. אפשר לבטל אפשרות זו כדי להשתמש בשמירה ללשונית בלבד. הסיסמה נפרדת ממפתחות API של Morning; אפשר לקבוע אותה דרך `APP_ACCESS_TOKEN` במאפייני Apps Script, באורך 16 תווים לפחות לאחר התקנת הבקנד החדש. `setupAccessCode` אינו מחליף סיסמה שכבר נקבעה.
- פגישות שלא שולמו לפני החודש הנבחר מסומנות כברירת מחדל. פגישות באותו חודש מוצגות ללא סימון. אפשר לשנות כל בחירה.
- תשלום עבור פגישות שלמות בלבד, לפי הסכומים שנשמרו לכל פגישה, גם אם תעריף המטופל השתנה.
- הודעת WhatsApp ניתנת לעריכה עם שם, חודשים, תאריכים, סכום וחתימה. פתיחת שיחה אינה שולחת את ההודעה.
- הבקנד קורא וכותב לפי כותרות העמודות. עדכון תשלום נעשה לפי מזהי פגישות ורק לאחר הצלחת ההפקה.
- בקשות הפקה נשמרות ביומן עמיד. ניתוק או לחיצה חוזרת אינם גורמים להנפקה חוזרת אוטומטית.

## הרצה מקומית

האתר הוא HTML/CSS/JavaScript ללא תלות בבנייה או ספריות חיצוניות. יש להגיש אותו דרך שרת HTTP מקומי, למשל `python -m http.server 8765 --bind 127.0.0.1`, ולא לפתוח כקובץ `file://`.

פתחו `http://127.0.0.1:8765/?demo=1` להתנסות עם נתונים בדויים. מצב ההדגמה אינו שומר נתונים, אינו שולח הודעות ואינו מפיק מסמכים.

## התקנת הבקנד

1. שמרו עותק של קוד Apps Script הנוכחי ועותק בדיקה של הגיליון. תחילה מומלץ לחבר את הקוד לעותק הבדיקה.
2. בפרויקט Apps Script הקיים, החליפו את קוד הבקנד בתוכן `apps-script/Code.gs`. אין להשאיר הגדרות כפולות של `doGet` או `doPost` בקבצים אחרים.
3. השאירו את `MORNING_API_KEY` ואת `MORNING_API_SECRET` במאפייני הסקריפט. הגדירו `MORNING_ENV` כ־`sandbox` לבדיקות. אין להעלות מפתחות ל־GitHub.
4. אם הסקריפט אינו קשור ישירות לגיליון, הגדירו `SPREADSHEET_ID` במאפייני הסקריפט. לבדיקות השתמשו במזהה עותק הבדיקה.
5. הריצו פעם אחת את `setupAccessCode` מהעורך. הפונקציה מוסיפה `APP_ACCESS_TOKEN` אם אינו קיים. העתיקו את ערכו ממאפייני הסקריפט ישירות להגדרות האפליקציה; אין צורך לשתף אותו בצ׳אט.
6. עדכנו את פריסת ה־Web App דרך **Deploy → Manage deployments → Edit → New version → Deploy**. יש לשמור על הרשאות הגישה הקיימות; הבקנד עצמו דורש קוד גישה לכל פעולה עם נתונים. כתובת ה־Web App שמסתיימת ב־`/exec` מופיעה בפרטי הפריסה.
7. בדקו פריסות ישנות פעילות: הגרסה הישנה החזירה נתוני מטופלים דרך GET ללא קוד גישה. יש לעדכן או להוציא משימוש פריסות ישנות של אותו פרויקט בהתאם לצורך.
8. בממשק החדש פתחו ⚙ הגדרות, הזינו את כתובת `/exec`, סיסמת הקליניקה והחתימה להודעות. הכתובת והחתימה נשמרות בדפדפן; הסיסמה נשמרת לפי בחירת ״זכור אותי במכשיר הזה״. אין להעלות סיסמה או מפתחות למאגר.

הגרסה החדשה דורשת API v2 ואינה מתחברת לבקנד הישן. יש לעדכן את שני הצדדים יחד.

## כותרות הגיליון

אין לסדר מחדש שורות ישנות באופן אוטומטי. הממשק יציג שגיאה אם מזהה חסר/כפול או אם לא ניתן לשייך פגישה למטופל יחיד.

`Patients` או `מטופלים`:

| כותרת | תוכן |
|---|---|
| מזהה מטופל | מזהה יציב, כגון PAT-… |
| שם מלא | שם המטופל |
| טלפון | טקסט, כולל האפס המוביל |
| תעריף ברירת מחדל | סכום לפגישה חדשה |
| סטטוס | למשל פעיל |

`Appointments` או `פגישות`:

`מזהה פגישה`, `תאריך ושעה` (אופציונלי), `תאריך`, `שם המטופל`, `סכום לתשלום`, `סטטוס תשלום`, `אמצעי תשלום`, `מספר חשבונית`, `morning_status`, `pdf_url`.

בעת הוספת פגישה חדשה הבקנד מוסיף, אם חסרה, עמודת `מזהה מטופל` בסוף הגיליון. בשורות ישנות הוא נעזר בהתאמה מדויקת ויחידה של שם המטופל. הקריאה עצמה אינה משנה שורות או כותרות. בחשבונית מרוכזת נשמר אותו מספר מסמך בכל הפגישות שנבחרו; מסך המסמכים מאחד אותן למסמך אחד.

## בדיקת החיבור

1. התחברו לעותק הגיליון ול־Morning sandbox.
2. ודאו שמופיעים התעריפים הנכונים, כולל תעריף שונה מ־350.
3. הוסיפו מטופל ופגישה. בדקו שהנתונים נכנסו לעמודות הנכונות.
4. בחרו רק חלק מהפגישות של מטופל, ופתחו את נוסח WhatsApp. בדקו שם, חודשים, תאריכים וסכום.
5. הפיקו חשבונית מס־קבלה בסביבת הבדיקות. בדקו את PDF המסמך ואת אמצעי התשלום ב־Morning.
6. בדקו שרק הפגישות שנבחרו סומנו כשולמו ושמספר המסמך והקישור נמצאים בעמודות הנכונות.

הקוד שומר על מסלול OAuth מהבקנד שסופק. הצלחת הפקה ושליחת מייל אמיתיים טרם נבדקה בסשן הפיתוח הזה. גם העברה בנקאית דורשת בדיקה עם חשבון Morning שלכם; אם החשבון דורש פרטי בנק נוספים, יש להשלים אותם לפני שימוש באמצעי הזה.

## שליחת חשבוניות למייל דרך Morning

נדרש להתקין ולפרוס מחדש את `apps-script/Code.gs` מגרסת עדכון המייל. הממשק מזהה את התמיכה באמצעות `supportsEmailDelivery` ואינו מנפיק מסמך בלי בדיקת נמען כשהבקנד עדיין ישן.

לפני ההפקה הבקנד מאתר לקוח קיים ב־Morning וקורא את כתובות המייל שלו. חלון התשלום מציג את הנמענים לבדיקה. לפני יצירת המסמך הבקנד בודק אותם שוב, ומעביר ל־Morning את מזהה הלקוח הקיים, `client.emails`, חתימה דיגיטלית ו־`attachment: true`. לפי [סכמת ה־API הרשמית של Morning](https://developers.morning.co/docs/openapi.bundled.json), כתובות `client.emails` הן הנמענים שאליהם נשלח קישור המסמך, ו־`attachment` מוסיף את קובץ המסמך להודעה. אין שימוש בנקודת קצה לא מתועדת לשליחה מחדש.

כשיש יותר מלקוח אחד באותו שם, נעזרים בהתאמת טלפון מדויקת. אם השיוך עדיין אינו חד־משמעי, מוסיפים לגיליון `Patients` עמודה אופציונלית `morning_client_id` ומזינים את מזהה הלקוח הנכון מ־Morning. ללא מייל תקין, כשהשליחה האוטומטית בכרטיס הלקוח כבויה או כשיש אי־התאמה בפרטים, ההפקה נעצרת לפני יצירת מסמך. לקוחות אינם נוצרים אוטומטית בזמן הפקה.

`emailRequested` מציין ש־Morning קיבל את בקשת ההפקה עם נמעני המייל; הוא אינו אישור מסירה לתיבת הדואר. גם סביבת sandbox עשויה לשלוח מייל אמיתי, ולכן בדיקת הקצה צריכה להיעשות רק עם נמען בדיקה שבחרתם. מסמכים שכבר הופקו ללא מייל אינם מופקים מחדש; יש להשתמש באפשרות השליחה בממשק Morning עבורם.

## תקלת הנפקה ויומן בקשות

`_TheraPayRequests` הוא גיליון מוסתר שנוצר בפעולת כתיבה ראשונה. אין למחוק אותו כחלק מניקוי נתונים.

- `done`: הפעולה הושלמה.
- `issued`: Morning החזיר מסמך והתגובה נשמרה. ניסיון חוזר עם אותו מזהה בקשה משלים את כתיבת הנתונים בגיליון בלי להפיק מסמך נוסף.
- `pending` / `unknown`: לא ניתן לאשר שהמסמך לא הופק. המערכת חוסמת הפקה נוספת עבור אותן פגישות, גם ממכשיר אחר. יש לבדוק ידנית ב־Morning לפני שחרור או התאמה של הרשומה; אין לאפס את היומן כדי ״לנסות שוב״.
- `rejected`: Morning דחה את הבקשה במפורש. אפשר לתקן את הפרטים וליצור בקשה חדשה.

עדכון הגיליון אינו עסקה אטומית. היומן מאפשר להשלים עדכון חלקי בלי הנפקה נוספת. אם הצלחת Morning לא הספיקה להישמר בגיליון, הרשומה נשארת במצב לא ודאי לבירור ידני.

## Vercel

`vercel.json` מגדיר אתר סטטי. `node scripts/build.mjs` מעתיק רק את ארבעת קובצי האתר ל־`dist`, כך שקוד Apps Script והבדיקות אינם חלק מקובצי האתר המוגשים. הבנייה אינה מתקינה תלויות.

השינויים הוכנו בענף `codex/mobile-monthly-collection` לבדיקת תצוגה מקדימה לפני עדכון האתר הראשי. המשתמש התקין ופרס את Apps Script ב־15.10.2026; בדיקת POST ללא קוד גישה אישרה API v2 ודרישת אימות, ללא גישה לנתוני המטופלים. בדיקת Morning מול החשבון בפועל עדיין נדרשת.

## בדיקות

`node --test tests/domain.test.js tests/backend.test.js tests/frontend.test.js` — בדיקות בחירת פגישות, סכומים, הודעות, אזור זמן, הרשאות, מיפוי עמודות, שיוך מטופלים, כפילויות והתאוששות משגיאות. בדיקות הממשק מדמות גם הפקה מוצלחת עם כשל ברענון שלאחריה ומוודאות שהחיבור וקוד הגישה נשמרים ושאין הנפקה נוספת.

`node tests/browser-smoke.cjs` — בדיקת דפדפן באמצעות Playwright מותקן. אפשר להגדיר `PLAYWRIGHT_CHANNEL=chrome` לשימוש ב־Chrome מותקן. הבדיקה בודקת רוחבים 320, 390, 768 ו־1280, ומדמה שרת ללא קריאות ל־Morning או לנתוני מטופלים אמיתיים.


## עריכת פרטים

לעדכון יכולת העריכה יש להחליף את קוד Apps Script ב־`apps-script/Code.gs`, לשמור ולפרוס גרסה חדשה באותה פריסה קיימת, ואז לרענן נתונים בהגדרות. אין שינוי במאפייני הסקריפט או במפתחות. הבקנד מחזיר `supportsEditing:true` לאחר העדכון.

ברשימת המטופלים כפתור עריכה מאפשר שינוי שם, טלפון, תעריף וסטטוס. שינוי שם שומר את שיוך הפגישות לפי מזהה קבוע, ותעריף חדש אינו משנה מחירי פגישות קיימות. לחיצה על פגישה פותחת פרטים ומשם עריכה של מטופל, תאריך וסכום. פגישות ששולמו או שיש עבורן הפקת מסמך לא פתורה חסומות לעריכה. השרת בודק שהרשומה לא השתנתה מאז פתיחת הטופס. בקשות שמירה כוללות מזהה למניעת כפילויות.


## משימות

כפתור משימות נמצא בכותרת האתר. יש תוכן בשורה אחת (עד 160 תווים), תאריך יעד אופציונלי ותזכורת מוקדמת: ללא, יום, יומיים או שבוע לפני. ברירת המחדל היא יום לפני. ללא תזכורת מוקדמת, הסימון מתחיל ביום היעד; ללא יעד, המשימה מופיעה ברשימה בלבד. הסימון בדשבורד מציג מספר בלבד ונשאר עד לסימון השלמה. ניתן לערוך משימה ולפתוח מחדש משימה שהושלמה. השעון נבדק גם בזמן שהאתר פתוח ובחזרה אליו, לפי יום ישראל.

יש להעתיק את Code.gs המעודכן ולפרוס גרסה חדשה באותה פריסה. אין צורך להוסיף גיליון ידנית: TheraPayTasks נוצר בעת שמירת המשימה הראשונה. getTasks/saveTask פועלים בנפרד מקריאת נתוני הקליניקה; תקלה בגיליון המשימות אינה חוסמת מטופלים ופגישות. כל שמירה כוללת מזהה בקשה, ובעריכה נבדקת גרסת המשימה למניעת דריסת שינוי ממכשיר אחר. זהו שלב המשימות והסימון בתוך האתר בלבד; אין משלוח Push או WhatsApp.
