# TheraPay

ניהול קליניקה למטפלת אחת: ממשק שמתחיל בסלולר, רישום ידני של פגישות, הודעות WhatsApp וחשבוניות מס־קבלה ב־Morning.

## מה נבנה

- מסך פתיחה עם דשבורד כהה, הוספת פגישה ומטופל וסיכומי נתונים. מסכים נפרדים למטופלים, פגישות, גבייה ומסמכים; ניווט תחתון בסלולר ותפריט צד במחשב. המבנה הוחלף לאפשרות הראשונה לפי בחירת המשתמש.
- חיווי גלוי למספר המטופלים והפגישות שהשרת החזיר. בעיית הפגישות החסרות בחיבור האמיתי עדיין דורשת בדיקה מול הגיליון; שינוי העיצוב אינו תיקון של מקור הנתונים.
- פגישות שלא שולמו לפני החודש הנבחר מסומנות כברירת מחדל. פגישות באותו חודש מוצגות ללא סימון. אפשר לשנות כל בחירה.
- תשלום עבור פגישות שלמות בלבד, לפי הסכומים שנשמרו לכל פגישה, גם אם תעריף המטופל השתנה.
- הודעת WhatsApp ניתנת לעריכה עם שם, חודשים, תאריכים, סכום וחתימה. פתיחת שיחה אינה שולחת את ההודעה.
- הבקנד קורא וכותב לפי כותרות העמודות. עדכון תשלום נעשה לפי מזהי פגישות ורק לאחר הצלחת ההפקה.
- בקשות הפקה נשמרות ביומן עמיד. ניתוק או לחיצה חוזרת אינם גורמים להנפקה חוזרת אוטומטית.

## הרצה מקומית

האתר הוא HTML/CSS/JavaScript ללא תלות בבנייה או ספריות חיצוניות. יש להגיש אותו דרך שרת HTTP מקומי, למשל `python -m http.server 8765 --bind 127.0.0.1`, ולא לפתוח כקובץ `file://`.

פתחו `http://127.0.0.1:8765/?demo=1` להתנסות עם נתונים בדויים. מצב ההדגמה אינו שומר נתונים, אינו שולח הודעות ואינו מפיק מסמכים.

## התקנת הבקנד

1. שמרו עותק של קוד Apps Script הנוכחי ועותק בדיקה של הגיליון. תחילה מומלץ לחבר את הקוד לעותק הבדיקה.
2. בפרויקט Apps Script הקיים, החליפו את קוד הבקנד בתוכן `apps-script/Code.gs`. אין להשאיר הגדרות כפולות של `doGet` או `doPost` בקבצים אחרים.
3. השאירו את `MORNING_API_KEY` ואת `MORNING_API_SECRET` במאפייני הסקריפט. הגדירו `MORNING_ENV` כ־`sandbox` לבדיקות. אין להעלות מפתחות ל־GitHub.
4. אם הסקריפט אינו קשור ישירות לגיליון, הגדירו `SPREADSHEET_ID` במאפייני הסקריפט. לבדיקות השתמשו במזהה עותק הבדיקה.
5. הריצו פעם אחת את `setupAccessCode` מהעורך. הפונקציה מוסיפה `APP_ACCESS_TOKEN` אם אינו קיים. העתיקו את ערכו ממאפייני הסקריפט ישירות להגדרות האפליקציה; אין צורך לשתף אותו בצ׳אט.
6. עדכנו את פריסת ה־Web App דרך **Deploy → Manage deployments → Edit → New version → Deploy**. יש לשמור על הרשאות הגישה הקיימות; הבקנד עצמו דורש קוד גישה לכל פעולה עם נתונים. כתובת ה־Web App שמסתיימת ב־`/exec` מופיעה בפרטי הפריסה.
7. בדקו פריסות ישנות פעילות: הגרסה הישנה החזירה נתוני מטופלים דרך GET ללא קוד גישה. יש לעדכן או להוציא משימוש פריסות ישנות של אותו פרויקט בהתאם לצורך.
8. בממשק החדש לחצו ״התחברות״, הזינו את כתובת `/exec`, קוד הגישה והחתימה להודעות. הכתובת והחתימה נשמרות בדפדפן; הקוד נשמר רק בלשונית הנוכחית.

הגרסה החדשה דורשת API v2 ואינה מתחברת לבקנד הישן. יש לעדכן את שני הצדדים יחד.

## כותרות הגיליון

אין לסדר מחדש שורות ישנות באופן אוטומטי. הממשק יציג שגיאה אם מזהה חסר/כפול או אם לא ניתן לשייך פגישה למטופל יחיד.

`Patients` או `מטופלים`:

| כותרת | תוכן |
|---|---|
| מזהה מטופל | מזהה יציב, כגון PAT-… |
| שם מלא | שם המטופל |
| טלפון | טקסט, כולל האפס המוביל |
| תעריף ברירת מחדל | סכום לפגישה חדשה |
| סטטוס | למשל פעיל |

`Appointments` או `פגישות`:

`מזהה פגישה`, `תאריך ושעה` (אופציונלי), `תאריך`, `שם המטופל`, `סכום לתשלום`, `סטטוס תשלום`, `אמצעי תשלום`, `מספר חשבונית`, `morning_status`, `pdf_url`.

בעת הוספת פגישה חדשה הבקנד מוסיף, אם חסרה, עמודת `מזהה מטופל` בסוף הגיליון. בשורות ישנות הוא נעזר בהתאמה מדויקת ויחידה של שם המטופל. הקריאה עצמה אינה משנה שורות או כותרות. בחשבונית מרוכזת נשמר אותו מספר מסמך בכל הפגישות שנבחרו; מסך המסמכים מאחד אותן למסמך אחד.

## בדיקת החיבור

1. התחברו לעותק הגיליון ול־Morning sandbox.
2. ודאו שמופיעים התעריפים הנכונים, כולל תעריף שונה מ־350.
3. הוסיפו מטופל ופגישה. בדקו שהנתונים נכנסו לעמודות הנכונות.
4. בחרו רק חלק מהפגישות של מטופל, ופתחו את נוסח WhatsApp. בדקו שם, חודשים, תאריכים וסכום.
5. הפיקו חשבונית מס־קבלה בסביבת הבדיקות. בדקו את PDF המסמך ואת אמצעי התשלום ב־Morning.
6. בדקו שרק הפגישות שנבחרו סומנו כשולמו ושמספר המסמך והקישור נמצאים בעמודות הנכונות.

הקוד שומר על מסלול OAuth ומבנה המסמך מהבקנד שסופק. הצלחת הפקה אמיתית טרם נבדקה בסשן הפיתוח הזה. גם העברה בנקאית דורשת בדיקה עם חשבון Morning שלכם; אם החשבון דורש פרטי בנק נוספים, יש להשלים אותם לפני שימוש באמצעי הזה.

## תקלת הנפקה ויומן בקשות

`_TheraPayRequests` הוא גיליון מוסתר שנוצר בפעולת כתיבה ראשונה. אין למחוק אותו כחלק מניקוי נתונים.

- `done`: הפעולה הושלמה.
- `issued`: Morning החזיר מסמך והתגובה נשמרה. ניסיון חוזר עם אותו מזהה בקשה משלים את כתיבת הנתונים בגיליון בלי להפיק מסמך נוסף.
- `pending` / `unknown`: לא ניתן לאשר שהמסמך לא הופק. המערכת חוסמת הפקה נוספת עבור אותן פגישות, גם ממכשיר אחר. יש לבדוק ידנית ב־Morning לפני שחרור או התאמה של הרשומה; אין לאפס את היומן כדי ״לנסות שוב״.
- `rejected`: Morning דחה את הבקשה במפורש. אפשר לתקן את הפרטים וליצור בקשה חדשה.

עדכון הגיליון אינו עסקה אטומית. היומן מאפשר להשלים עדכון חלקי בלי הנפקה נוספת. אם הצלחת Morning לא הספיקה להישמר בגיליון, הרשומה נשארת במצב לא ודאי לבירור ידני.

## Vercel

`vercel.json` מגדיר אתר סטטי. `node scripts/build.mjs` מעתיק רק את ארבעת קובצי האתר ל־`dist`, כך שקוד Apps Script והבדיקות אינם חלק מקובצי האתר המוגשים. הבנייה אינה מתקינה תלויות.

השינויים הוכנו בענף `codex/mobile-monthly-collection` לבדיקת תצוגה מקדימה לפני עדכון האתר הראשי. המשתמש התקין ופרס את Apps Script ב־15.10.2026; בדיקת POST ללא קוד גישה אישרה API v2 ודרישת אימות, ללא גישה לנתוני המטופלים. בדיקת Morning מול החשבון בפועל עדיין נדרשת.

## בדיקות

`node --test tests/domain.test.js tests/backend.test.js` — בדיקות בחירת פגישות, סכומים, הודעות, אזור זמן, הרשאות, מיפוי עמודות, שיוך מטופלים, כפילויות והתאוששות משגיאות.

`node tests/browser-smoke.cjs` — בדיקת דפדפן באמצעות Playwright מותקן. אפשר להגדיר `PLAYWRIGHT_CHANNEL=chrome` לשימוש ב־Chrome מותקן. הבדיקה בודקת רוחבים 320, 390, 768 ו־1280, ומדמה שרת ללא קריאות ל־Morning או לנתוני מטופלים אמיתיים.
