# הקמת פיילוט ההפצה

הקוד נמצא בענף `codex/onboarding-pilot`, בנפרד מהאתר הפעיל. טרם בוצע חיבור אמיתי לחשבון Google חדש. ההדגמה מקומית ואינה פונה ל־Google או ל־Morning.

## הדגמה ובדיקות

הריצו `node scripts/build.mjs`, ואז הגישו את תיקיית `dist` בשרת מקומי בפורט 8766. פתחו `/onboarding.html?demo=1`. בדיקות: `node --test tests/*.test.js`.

## הגדרה חד־פעמית של מנהל ההפצה

1. צרו פרויקט Google Cloud נפרד לפיילוט. הפעילו Google Drive API, Google Sheets API ו־Apps Script API.
2. הגדירו מסך הסכמה ב־Google Auth Platform. בשלב Testing הוסיפו במפורש את חשבונות הניסוי כ־Test users.
3. צרו OAuth Client מסוג Web application. הוסיפו Authorized JavaScript origins של כתובת הפיילוט, ללא נתיב. לפיתוח הוסיפו גם `http://localhost`, `http://localhost:8766`, `http://127.0.0.1` ו־`http://127.0.0.1:8766`. אין צורך ב־Client Secret באתר.
4. בחשבון מנהל ההפצה צרו פרויקט Apps Script חדש ונפרד. הכניסו בו את `distribution/Registry.gs`. במאפייני הסקריפט הגדירו `REGISTRY_GOOGLE_CLIENT_ID` עם ה־Client ID הציבורי מהסעיף הקודם.
5. הריצו `setupRegistry` ואשרו הרשאות. הפעולה יוצרת גיליון פרטי ובו שלוש עמודות: שם, מייל, שימוש. מזהה הגיליון נשמר במאפיין `REGISTRY_SPREADSHEET_ID`. אין לשתף את הגיליון עם המשתמשים.
6. פרסו את Registry כ־Web App שפועל כמנהל ההפצה ומאפשר גישה ל־Anyone. הכתובת אינה מאפשרת קריאת משתמשים: רישום דורש Google ID token תקין וסימון שימוש דורש קבלה חתומה. העתיקו את כתובת `/exec`.
7. הגדירו `GOOGLE_OAUTH_CLIENT_ID` ו־`REGISTRY_URL` כמשתני Build בפרויקט Vercel נפרד, או ערכו את `onboarding-config.js`. אלו פרטים ציבוריים בלבד. אין להכניס לשם מפתחות Morning, סיסמאות או OAuth Client Secret.
8. פרסו את הענף בפרויקט Vercel של הפיילוט בלבד, והוסיפו את מקור הכתובת לרשימת ה־origins של Google. האתר הפעיל אינו יעד פריסה של פיילוט זה.

## מה המשתמש עושה

המשתמש מתחבר עם Google ומאשר הרשאות. האשף יוצר גיליון פרטי, קוד Apps Script ופריסה בחשבון שלו. הרשאות ניהול פרויקטי הסקריפט רחבות; הקוד משתמש בהן לפרויקט שנוצר עבורו בלבד. Google עשוי לדרוש הפעלת Apps Script API בהגדרות החשבון, ולאחר יצירת הפרויקט גם אישור הרצה נוסף. האשף מכין מסך אישור פרטי של הפרויקט ומציג כפתור ״אישור הרשאות ב־Google״. אין מעבר לעורך קוד. המסלול החדש עדיין דורש בדיקה חיה מול Google.

המשתמש בוחר סיסמת קליניקה של 16 תווים לפחות, מכניס מפתחות Morning, ובוחר לקוחות לייבוא ותעריף לכל אחד. כל לקוח שנבחר חייב טלפון ומייל תקינים. שינוי פרטי קשר ב־Morning מחייב אישור מפורש במסך הסיכום; הגדרת שליחת המייל של Morning נשמרת. בדיקת החיבור והייבוא אינם מפיקים מסמכים.

נוסח המייל הוא טקסט נוסף במסמך שנשלח דרך Morning; הוא אינו מחליף את כל עיצוב המייל או נושאו. נוסח WhatsApp כולל שם, חודש, תאריכים, סכום ושם הקליניקה.

## הפרדת מידע והמשך הקמה

- מפתחות Morning והסיסמה נשמרים במאפייני הסקריפט הפרטי של המשתמש. Access token של Google נשמר בזיכרון הדפדפן בלבד.
- שחזור הקמה שומר רק מזהי קבצים, פריסה וחשבון. האשף בודק בעלות וסימון פרויקט לפני שינוי קבצים קיימים. ניסיון חוזר בייבוא מזהה מטופלים לפי מזהה Morning ואינו מוסיף אותם שוב.
- כשל רשת בדיוק בזמן יצירת משאב, לפני קבלת מזההו, עלול להשאיר קובץ יתום. במקרה כזה יש לבדוק ב־Drive לפני ניסיון יצירה נוסף.
- מנהל ההפצה מקבל שם, מייל וסימון שימוש ראשון בלבד. שימוש מסומן לאחר כתיבה מוצלחת בקליניקה; הסימון אינו מדד פעילות רציף או תאריך כניסה אחרון. כשל בשירות הרישום אינו עוצר את הקליניקה.
- בחירת ״זכור אותי״ שומרת את סיסמת הקליניקה בדפדפן באותו מנגנון הקיים באפליקציה. ללא הבחירה היא נשמרת רק למשך ההפעלה.

## לפני הפצה רחבה

נדרש ניסוי אמיתי עם חשבון Google נוסף: הרשאות, יצירת משאבים, חידוש הקמה, ייבוא לקוחות, התאוששות משגיאות ופעילות לאחר תום תוקף הרשאת Google. מסלול ההדגמה ובדיקות מדומות אינם מאמתים זאת.

Registry משתמש ב־Google tokeninfo לאימות ID token בפיילוט. לפני הפצה רחבה יש להחליפו באימות JWT בצד שרת לפי הנחיות Google, להוסיף הגבלת קצב, ולהשלים את דרישות Google לפרסום מסך ההסכמה והרשאות האפליקציה. בדיקת שליחת מסמך אמיתי תבוצע רק לאחר הגדרה ובחירה מודעת של סביבת Morning המתאימה.

מקורות: [הגדרת Google Identity](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid), [הרשאות בדפדפן](https://developers.google.com/identity/oauth2/web/guides/use-token-model), [אימות ID token](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token), [יצירת פרויקט Apps Script](https://developers.google.com/apps-script/api/reference/rest/v1/projects/create).
